# Carry-forward obligations for later units

These are requirements that fixes in earlier units created for later units. Every build brief must read this file.

- **asc-engine ingest (U11 and every write path):** reject `git.commit` and `git.tag` extras on every ingest path except git import (`canonicalise_commit` / `canonicalise_tag`).
- **Callers of `export_commit` / `export_tag`** handle the `Result`. Raw bytes are verified against tree, parents, idents and message.
- **`Signature`** has private fields. Build it with `Signature::new`, which rejects LF, `<`, `>` and NUL.
- **Object decode** validates `Change`, `Changeset` and `ChunkList` invariants. Full apply/leafdiff validation stays in asc-engine ingest.
- **Paths:** `checkout_safe` rejects any backslash. `windows_valid` matches git's `is_valid_win32_path`.
- **`FileMeta` is dropped.** Envelope kind 5 is reserved.
- **No LFS anywhere:** no LFS fields, alias keys, pointer parsing, LFS API or LFS copy jobs. Pointer files are plain blobs.
- **asc-store reconcile, after U08/U09:**
  - `CacheDir` and `Tiered` `put` must verify on write and repair corrupt values, so they pass the extended conformance suite.
  - Migrate the callers to `decode_stored_capped(stored, max)` with per-class caps, then delete the 256 MiB `decode_stored` wrapper.
- **`canonicalise_tag`** must reject `type` other than `commit` at import, not only at export.
- **`parse_tag` rejects unknown headers.** This is stricter than git. If an imported history tag has extra headers, keep it raw instead of failing the import.
- **Import round-trip invariant (asc-git import, U33):** after building each changeset from a raw git commit or tag, call `export_commit`/`export_tag`. Store it only if the result equals the original raw bytes (same SHA-1). Otherwise fail the import of that object. An `asc` header whose copies do not map to `Change::Write` entries is rejected this way, so nothing unexportable is ever stored.
- **`ObjKey::ChangeMeta` (`m/`) and envelope kind 6 are reserved (SPEC §2.2, §3.1, §20.2).** `OBJ_KIND_CHANGE_META = 9` is reserved in `repo.proto` (U41). C01 adds them to the built `asc-core`/`asc-store` enums; no other unit may use kind 6, key prefix `m/` or ObjKind 9.
- **Graph boundary (U31):** the built `GraphSource::get` has no `Boundary` result. U31 owns adding `GraphSource::get -> Result<NodeOrBoundary>` (a `Boundary` variant for ids recorded in `history_boundary`) to `crates/asc-engine/src/graph.rs`. `Graph::merge_base`/`is_ancestor`/`log` hand a boundary to an optional `RemoteHistory` hook, which calls `MergeBase`/`IsAncestor`/`Log` with the boundary ids.
- **Skip pointers (U14b):** `JumpIndex::jump` is synchronous, so `graph_skip.rs` loads `skip.v1` for each node when `GraphSource` loads it (a wrapping `GraphSource`) and answers `jump` from memory.
- **Raw git in tests (U01b, U15):** the test-only `Command::new("git")` lines in asc-engine carry `// lint:allow-raw-git` (SPEC §11.4); asc-engine cannot use `RealGit` (crate cycle).
- **Work tree access (every CLI and daemon unit) [audit: asc-rm-add-follow-symlinked-parent]:** a tracked path under a symlinked or reparse-point ancestor is outside the work tree (git's `has_symlink_leading_path`) and is never read, written or deleted. Take every work tree file path from `asc_wc::SafeRoot::resolve` (one `SafeRoot` per command; `None` means treat the path as missing), and use `SafeRoot::remove_file` / `remove_empty_parents` to delete. `build/lint/no-raw-worktree-fs.sh` fails on `fs_path(`, hand-built `root.join(` / `toplevel().join(` paths and `read_dir(` in `crates/asc/src`; a justified exception carries `lint:allow-worktree-fs`. New daemon crates extend the lint's path list.
- **Local ref moves (every CLI unit):** go through `Ctx::update_local_refs` only (SPEC §9.4.1); the synthetic index follows set 0, not only HEAD (SPEC §9.4).
- **Read-only cache tier (U20, recorded amendment to built U08) [audit: object-stack-selector-single-owner-blocks-remote-tier]:** add `CacheDir::open_read_only(root)` in `crates/asc-store/src/cachedir.rs`. Its `put` returns `Ok` without writing, and a corrupt read returns `Error::Corrupt` without deleting the file (SPEC §3.5).
- **Ref lint (U20, recorded amendment to built U01b) [audit: engine-local-ref-moves-bypass-chokepoint]:** in `build/lint/no-raw-git.sh`, `check_refs_update crates/asc/src/cli` becomes `crates/asc/src`, excluding `crates/asc/src/refs_guard.rs`. Engine code never moves a local ref (SPEC §9.4.1).
- **S3 credentials (U32, recorded amendment to built U08) [audit: store-must-not-spawn-git]:** `asc-store` no longer runs `git credential fill`; `s3::open_with` and `Bucket::from_url_with` take optional `S3Credentials`. U32: S3 remotes get credentials from asc_git::credential::fill only when asc.s3.credentialHelper=true; libraries never spawn git.
- asc-graph: `canon::Value` derives plain `Deserialize`. Anything decoding untrusted bytes into a `Value` must go through `model::Parsed` (depth-bounded seed), never `postcard::from_bytes::<Value>` directly.
- **Branchless (SPEC §21, PLAN §B) [audit: branchless-folded]:** the migration-mode change-id tier (`blake3_derive("asc v1 change import", cs)[..16]`) lives in `crates/asc-core/src/change_migrate.rs` (B18a), not in the built C01 (`change.rs` is unchanged). Every command that writes a changeset also drives `DraftHeadSink` through C04's sink call (B03), in both modes, in the same transaction. Local git commands print identically with `asc.branchless` true and false (the compat suite runs both). The `repo.proto` fields for the commit cloud are added by the follow-up unit B07, not by rewriting U41.
- U32 (and any fetch caller): the engine enforces the fast-forward ancestry budget (`sync::local_ancestor` stops with `Error::AncestryBudget` after `SyncOptions.ancestry_budget` changesets, default 100,000, and refuses the ref move). U32 only maps the config key `asc.fetch.ancestryBudget` to `SyncOptions.ancestry_budget` and prints the error.
- U33 import: every GitTreeOverride stored on import must pass asc_git::tree_override::verify against the asc tree being created (follow-up U33x if U33 landed without it)
- GX (after G07): one shared `Budget` in asc-graph threaded through detect, lock, link and select (caps on manifests, workspaces, packages, edges and closure work, plus a total time/visit budget per derive). Replace the per-file caps, and add a fuzz target (O07) over all detectors.
- asc-engine tree diff: one-sided subtrees (Emit frames, i.e. wide added/deleted directories) still load sequentially. Add the same LOAD_WINDOW prefetch if the O05 benchmarks show it (clone/checkout of a new subtree).
- U32/U39 (bucket remotes): construct refs with `BucketRefs::connect` (probe at construction; fail closed with NoExclusiveCreate) rather than `new`/`from_url_with`, so a store without conditional writes is refused before any work.
- asc-rpc client (U42): `loopback()` must accept only `localhost` or a loopback IP literal for plaintext bearer-token transport; U42 must add a test that `127.example.com` and `localhost.evil` are rejected.
- asc-engine branchless guard (B28, security): `DenyList::denies` must not fail open on a path that is not UTF-8 (match `String::from_utf8_lossy` of the whole path and of each component), and deny globs must be case-insensitive (`GlobBuilder::case_insensitive(true)`), so `.ENV` and `KEY.PEM` are held. Add regression tests for both.
- asc CLI config writes (security): `write_file` must keep the existing config file's mode on the `.lock` file before the rename (Unix `fchmod(st_mode & 0o7777)`, as git does), and create a new file without widening beyond `0o666 & !umask`; a `chmod 600` config holding credentials must stay 600 after `asc config` edits. Add a Unix test.
- asc-git import speed (efficiency, after U35 23b99e7): the 1 GiB gate now holds (839 MiB peak) but ASC import went from 65–105 s to 160–180 s because blob hashing is capped at HASH_WORKERS = 3. Replace the fixed worker cap with a byte-weighted semaphore (a memory budget charged by `Odb::blob_size` plus the delta-chain base estimate), so small blobs hash on every core and large chains serialise, and/or a shared bounded gix delta-base cache. Target: ASC import at or below 105 s with peak RSS under 1 GiB; the O05 benchmarks track it.
- **Trusted workspaces (security, SPEC §11.4):** every code path that opens a workspace (the daemon, `asc api --stdio`, MCP stdio, the VFS mounts, and any new command that calls `Projection::open` or `WsCtx::open` itself) must go through `cli::common::discover`/`admit` (the ownership, `safe.directory`, ASC_HOME-containment and `state.db`-registration gate) before it reads repo-local config or runs anything the repo names. Do not call `Projection::open` on a user-supplied path and trust the result. `asc init`'s existing-repo probe (`init.rs`) still calls `Projection::open` directly; route it through the gate when init is next touched.
- asc-graph .NET detector (security, after the round-3 sweep): `affected` must fail closed. (a) An `<Import Sdk=...>` is skipped only when `Sdk` is a plain literal (no `$(`, `@(`, `%`); otherwise the import resolves to a scanned build file or marks the project opaque. (b) Replace the `redirects_import` denylist with a fail-closed rule: any property defined in an applied build file and used in an Import `Project` path marks the project opaque (this covers NuGetPackageRoot, RestorePackagesPath, RestoreOutputPath, ProjectAssetsFile, VSToolsPath, SolutionDir and the Pkg* properties). (c) Claim `Directory.Build.rsp`, since `-p:` switches there set properties without XML. Regression tests for each.
- **Mirror sources (security, after 9b2e60b):** the `RepoAdmin.init` handler must call `MirrorSources::set` (client policy: https or ssh on the Forgejo host or the allow-list) for a client `mirror_url`, and `set_configured` only for values from the server config file. Wire a `[forgejo] mirror_hosts` config key into `MirrorConfig.allowed_hosts` (`from_serve` passes an empty list today). A Forgejo configured as plain `http://` no longer syncs; keep that fail-closed unless an explicit operator opt-in is added.
- **Turbo Stage 2 scope (security, after 132aa2e):** `lib.rs` never installs a `ScopeSource`, so every deployment uses the Stage 1 fallback (trusted tokens, else `dev-<principal>`). When K07 is live, install a `ScopeSource` backed by the internal authz answer so Actions tasks get `pr-<n>` from their task identity, not from a header.
- **Work tree paths (security, after bf84bda):** when the diff and log units land, `cli/diff/sides.rs` (`fs_path`) and `cli/log/emit.rs` (`toplevel().join(".mailmap")`) must go through `asc_wc::SafeRoot`, and `cli/diff/noindex.rs` `read_dir` needs a `lint:allow-worktree-fs` marker with a reason, or `no-raw-worktree-fs.sh` fails CI.
- **Clean-HEAD build (process):** checkers verify on the shared working tree, which hid duplicate manifest keys, a duplicate `mod` line and an uncommitted `shim.rs` that HEAD declares. Each unit's check must also build a clean worktree of the commit (`git worktree add --detach`), and run `cargo clean -p asc-rpc` there if its build script reports a stale proto path from another worktree.
- **GC cluster fence (after 9738c80):** `PgClusterLock` (session `pg_advisory_lock_shared` for pushes, exclusive for sweep batches) is tested only against a fake `ClusterLock`. Add a real-Postgres integration test (two server instances, one database: a sweep cannot delete an ingested-but-uncommitted object) when the Postgres test service lands (I-units). The bucket-mode `thaw` keeps a small read-check-delete window until object_store offers a conditional delete.
- **Cache role repo identity (after 2cf264a):** cached objects are confirmed upstream per (principal, repo, key) every 60 s, so a repo deleted and recreated under the same name can be served stale objects for up to 60 s. Close it by returning a stable repo id or generation in the authz probe or `HasObjects` (proto + asc-rpc change) and keying the cache namespace on it.
- **GIT_DIR + GIT_WORK_TREE discovery (security, after 4a92c25):** `cli::common::discover` builds the projection with `Projection::open(work_tree)` when both are set, which re-reads `<work_tree>/.git`. With an explicit `GIT_DIR` it must build the projection from `GIT_DIR` and only check that the work tree matches the registered mount, never follow the work tree's gitfile. Then move the agent-hook snapshot (`claude_hook::save_dirty`) in-process on the already-admitted `Ctx` to remove the per-step check-then-spawn window.
- **MCP is forge-neutral (SPEC §22.1 M-D1, M-D11, M-D12):** no MCP code path may require Forgejo; auth goes through asc serve's authorizer; the Forgejo fork carries no source-control MCP logic.
- **MCP auth = git auth; one authorizer:** `/mcp`, `asc mcp --remote`, git smart-HTTP and RPC all verify tokens through `asc_rpc::auth::Authorizer` with the same cache and the same per-repo read and write scopes. `asc mcp --remote` gets its credential from the resolver `asc fetch` uses (`ASC_TOKEN`, then the git credential helper). Do not add an MCP identity system, an MCP-only token format or a second verifier. OAuth/OIDC (M33) is optional and only another way to present a credential that resolves through the same authorizer. A token is never forwarded to another API (no passthrough).
