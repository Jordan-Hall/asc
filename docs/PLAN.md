# asc implementation plan

Normative design: `docs/SPEC.md`. This file orders the work into **implementation units**. Each unit is small (one crate module or one Go package), owns a disjoint set of files, names its dependencies, and has **one acceptance command**. A unit is done when its acceptance command passes on a clean checkout, `cargo clippy --workspace --all-targets -- -D warnings` stays green, and no file outside the unit's owned list was changed (except `Cargo.lock`, one-line `mod`/`pub mod`/`pub use` registrations of the unit's own new files in their parent module file (`lib.rs`, `main.rs`, any `mod.rs` or `<dir>.rs`, including `cli/mod.rs`); creating a missing parent `mod.rs` that contains only such lines (the first unit to land creates it, later units add their line); and adding its own crate to `members` in the root `Cargo.toml`, which every unit may do) [audit: module-registration-exception-too-narrow].

**Rules for implementers (people or agents)**

- Agents run at effort ≤ medium. Read the SPEC sections cited in the brief before coding; do not re-decide anything the SPEC fixes.
- **Read `docs/CARRY.md` before every unit [audit: u01-v11-delta-unowned].** Units U01–U12 and U14 are built (U01–U10 as v1.0 code, updated by CARRY.md); U15 is in progress. Their v1.1–v1.3 deltas are U01b and the CARRY items [audit: status-stale-u11-u12-u14-built].
- Strong types: every id is a newtype; no `String` for paths or refs past the CLI boundary; errors via `thiserror` per crate, `anyhow` only in `crates/asc/src/main.rs`.
- No `unsafe` outside `asc-vfs::projfs::ffi` (which also wraps the `CreateFileW` that U57 uses), `asc-vfs::fuse::passthrough`, `asc-codeintel::vectors` (usearch FFI, cargo feature `ann`, SPEC §15.2) [audit: codeintel-folded], `asc-rpc::ipc` (Windows DACL only) and `asc::shim` (Windows console control handler only). Each starts with `#![allow(unsafe_code)]` or carries it on the specific item; the workspace lint is `unsafe_code = "deny"` (SPEC §15.2). U16a uses `same-file` for file identity, and U53c registers the logon task with `schtasks.exe /Create /XML` (no COM) [audit: unsafe-forbid-and-allowlist].
- Tests live next to the code (`#[cfg(test)]`) or in the unit's owned `tests/` files. Integration tests needing Docker, ProjFS, FUSE, turbo or ASC's repo are `#[ignore]` and gated behind the features named in the acceptance command.
- Pinned dependency versions are in SPEC §3/§4 and `docs/research/rust-stack.md` §10. Dependencies are pinned once in `[workspace.dependencies]` and units reference `workspace = true`. A unit that needs a crate not yet pinned may add exactly one exact-version line per crate to `[workspace.dependencies]`; this is allowed like the `mod` registration. The crate must pass `cargo deny` [audit: workspace-deps-rule-blocks-later-units].
- **SPEC v1.1–v1.3 user decisions are fixed:** default branch `master` (never `main`); git-identical CLI and the `git` shim; **no IDE git plumbing** (no full projection, no git-index staging, no import of `git commit`, no `git-remote-asc`); the built-in project graph; Scion-core efficiency budgets; stacked changes and stacked PRs as additive verbs (SPEC §20; units C01–C52); **branchless by default** with the opt-out commit cloud, user refs, the pre-upload secret hold and purge (SPEC §21; units B01–B28), which replaces the old "nothing uploaded before `asc push`" rule. Do not reintroduce removed mechanisms.
- **Running git:** every git child process goes through `asc_git::realgit::RealGit::command()` (SPEC §11.4). `Command::new("git")` is forbidden outside test fixtures of crates below asc-git (marker `lint:allow-raw-git`); U01b's `no-raw-git.sh` fails on it [audit: no-raw-git-lint-fails-built-code].
- **Acceptance before U25 [audit: cli-unit-acceptance-uses-sibling-commands]:** an acceptance test may run only CLI commands owned by the unit itself or by a declared dependency. Fixtures are built with `crates/asc/tests/support/mod.rs` (owned by U20: engine/state builders for repos, commits, branches and staging) or with real git through `RealGit`.
- **Trust boundaries (SPEC §15.4) are fixed.** More validation of a trusted component needs a SPEC change, not a unit-level decision.
- **Compatibility:** every CLI unit declares the flags, placeholders and atoms it implements as `pub const NATIVE: &[NativeSpec]` in its own `cli/<cmd>.rs` (the native table in `crates/asc/src/native.rs`, owned by U20, collects them), and adds compat cases under `tests/compat/scenarios/<cmd>-*.t` (SPEC §17.1).
- **Stubs and extension points [audit: ownership-violations-extension-points]:**
  - U20 creates one file per command in SPEC §11.2 and §12A.9, `crates/asc/src/cli/<cmd>.rs`, each holding the clap `Args` struct and `pub async fn run(ctx: &Ctx, a: Args) -> Result<ExitCode>` that returns "not supported yet" (exit 129). `cli/mod.rs` only lists them and is edited after U20 only by registration lines (the general exception) [audit: module-registration-exception-too-narrow]. The implementing unit owns and replaces its stub file (and its `native_<cmd>.rs` registration). The `asc ci` stub is `crates/asc/src/cli/ci/mod.rs` (there is no `cli/ci.rs`); U62 replaces it [audit: unowned-cli-commands].
  - U20 also defines these traits in `crates/asc/src/ext.rs`, each with a no-op or local default, selected in `Ctx::open` from a registry of `OnceLock<Box<dyn …>>` setters: `SyntheticIndexSink { on_commit, on_head_moved }` (U36 → `crates/asc/src/index_sink.rs`); `HistorySelector -> (Arc<dyn HistoryApi>, Arc<dyn BlameApi>)` (U50 → `crates/asc/src/remote/server.rs`); `ProjectsSelector -> Arc<dyn ProjectsApi>` (G10 → `crates/asc/src/remote/projects.rs`) [audit: historyapi-impl-split]; `RefTxnHook { prepared, committed, aborted }` (U22 → `crates/asc/src/hooks_runner.rs`) [audit: hooks-must-vs-list]; `WorkspaceFactory { plain | virtual, convert_plain(ws) }` (U53a → `crates/asc/src/daemon/workspace_factory.rs`; the default `convert_plain` is a no-op for plain workspaces and "not supported yet" for virtual ones) [audit: worktree-convert-plain-unowned]; `RewriteSink { fn record(&self, new: ChangesetId, preds: &[ChangesetId], kind: RewriteOp, op: OpId) }` (called by the command that writes the changeset; SPEC §20.3 sink contract) [audit: rewrite-sink-contract-insufficient-and-double-owned] and `OpSink { fn begin(&self, argv: &[OsString]) -> OpId; fn end(&self, op: OpId); fn snapshot_wc(&self) }` (C04 → `crates/asc/src/stack/sinks.rs`; SPEC §20.3) [audit: stacks-design-not-folded]; `RemoteObjectsSelector(&RemoteSpec) -> Option<Arc<dyn Objects>>`, a small registry keyed by remote kind (bucket: U32 → `crates/asc/src/remote/bucket.rs`; server: U50 → `crates/asc/src/remote/server.rs`; default none), which `Ctx` uses as the remote tier of the SPEC §3.5 object stack. `Ctx` itself builds the `asc.cache.*` tiers; `NoRemote` (always misses) lives in `ext.rs` [audit: object-stack-selector-single-owner-blocks-remote-tier, ci-tier-stack-config-undefined-unowned]. `SyntheticIndexSink` also has `on_stage_changed(ws, paths)`, called after every change to stage set 0 (SPEC §9.4) [audit: turbo-index-reflects-head-breaks-staged-contract].
  - **Local ref updates [audit: local-ref-update-chokepoint]:** `Ctx::update_local_refs(txn: RefTxn, reflog_msg, staging: StagingAfterMove)` (U20) is the only way CLI code moves a local ref (SPEC §9.4.1). It runs `ext::RefTxnHook` (prepared → CAS → committed | aborted), appends the reflog, calls `OpSink`/`RewriteSink` bookkeeping, and calls `ext::SyntheticIndexSink::on_head_moved` when HEAD's commit changes, and, unless the caller passes `StagingAfterMove::Set(rows)`, rebases the stage rows of set 0 across the HEAD move (default `Keep`; SPEC §9.5) [audit: staging-overlay-breaks-on-head-moves]. **Engine code never moves a local ref (SPEC §9.4.1):** an engine function whose effect includes local ref moves (`fetch`, `clone_minimal`, `push`'s remote-tracking update, restack execution) returns the planned `RefTxn`, and the CLI applies it through `Ctx::update_local_refs`. The CLI's `Engine` is built over `ReadOnlyRefs<SqlRefs>`, whose `update` returns `Error::ReadOnly` [audit: engine-local-ref-moves-bypass-chokepoint]. Every CLI unit that moves a ref (commit, branch, tag, reset, update-ref, merge, cherry-pick, revert, rebase, bisect, stash, fetch/push/pull remote-tracking updates, `worktree add -b`, stack verbs) calls it.
  - **Server extension points [audit: asc-serve-no-handler-or-route-extension-points]:** U42's `RepoHandlers` (one `Arc<dyn …>` per RPC group) and U43a's `HttpRoutes` and `GrpcServices` registries are filled by one registration line per unit in `crates/asc-serve/src/lib.rs` (U43b, U45, U47, U48a–U48d, U49, U66, U67, U68, U70, U72, U75, G09, C18–C22, C29, C30a–C30d, C50), which the general exception allows.
  - **Recorded amendments (stacks):** a few C units make one named hunk in a file another unit owns (table in §C). The hunk is listed in the C unit's brief and is allowed like the `mod` registration.
  - **Recorded amendments (branchless) [audit: branchless-folded]:** the B units make a few named hunks in files other units own (table in §B). Each hunk is listed in the B unit's brief and is allowed like the `mod` registration. Built units (U41, U14b and the rest of U01–U16) change behaviour only through the follow-up unit named in the table, never by rewriting their briefs.
  - **Recorded amendments (MCP) [audit: mcp-folded]:** the M units make a few named hunks in files other units own (table in §M). Built units (U41) are changed only through the follow-up units M01a and M01b; their briefs are not rewritten. Each hunk is listed in the M unit's brief and is allowed like the `mod` registration.
  - **Recorded amendments (codeintel) [audit: codeintel-folded]:** the I units make a few named hunks in files other units own (table in §I). Each hunk is listed in the I unit's brief and is allowed like the `mod` registration. Built units (U41, U14b) are not changed.
  - **Recorded amendments (non-stack) [audit: engine-local-ref-moves-bypass-chokepoint, object-stack-selector-single-owner-blocks-remote-tier]:** U20 makes two named hunks in built units' files: `build/lint/no-raw-git.sh` (U01b): `check_refs_update crates/asc/src/cli` becomes `crates/asc/src`, excluding `crates/asc/src/refs_guard.rs` (the one file that writes refs); and `CacheDir::open_read_only(root)` in `crates/asc-store/src/cachedir.rs` (U08; CARRY.md). Both are allowed like the `mod` registration.
  - **Child processes [audit: hook-child-path-real-git]:** every spawn of a hook, alias, editor, driver, `rebase --exec`, `bisect run` or `git-<name>`/`asc-<name>` external command goes through `asc::child::command()` (U20, `crates/asc/src/child.rs`), which applies SPEC §9.4.1's child PATH. Only `RealGit` children bypass it. Registering an implementation is one line in `main.rs`, which the general exception allows.

Dependency direction (strict) **[audit: crate-cycle-statedb, historyapi-cycle]**: `asc-core ← asc-graph ← asc-engine`; `asc-core ← asc-store ← asc-engine ← asc-state ← asc-git ← asc-wc ← asc-vfs ← asc`; `asc-rpc` depends on `asc-engine` (and implements `HistoryApi`, `BlameApi` and `ProjectsApi` remotely, SPEC §4.3); `asc-serve` on `asc-rpc`, `asc-git`, `asc-state`; `asc-ci` on `asc-wc`, `asc-git`, `asc-rpc`; `asc-sim` (dev only) on `asc-serve`; `asc-mcp` on `asc-rpc` and `asc-engine` (never on `asc`) [audit: mcp-folded]; `asc` and `asc-serve` on `asc-mcp` (feature `mcp`, on by default); `asc-codeintel` on `asc-engine` [audit: codeintel-folded]; `asc-serve` on `asc-codeintel` and `asc-embed` (feature `codeintel`), `asc` on `asc-codeintel` (daemon overlay and local helper, feature `codeintel`; no `asc-embed`); `asc-mcp` reaches the service through `asc-rpc` only; `asc` on everything (features `serve`, `vfs-projfs`, `vfs-fuse`, `mcp`, `codeintel`).

**Parallelism notation:** units in the same `‖ group` have disjoint files and no dependency on each other, so they can run concurrently once their dependencies are done.
